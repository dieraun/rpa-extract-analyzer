# 安全模型与威胁边界

本文档描述 `rpa-loader-analyzer` 的攻击面、已实施防护和已知限制。工具面向**合法授权**
的本地研究场景，不承诺对任意恶意样本“绝对安全”。

## 1. 资产与信任边界

受保护资产：

1. 原始游戏目录中的 `loader.pyo`、`*.rpa` 及其他资源；
2. 运行工具的主机（不执行不可信代码、不访问网络、不被路径穿越写入任意位置）；
3. 用户指定的独立输出目录。

信任边界：

- 游戏文件、RPA 索引、pickle 字节流、资源名、媒体文件全部视为**不可信输入**；
- 由 AST 分析器产生的规则 JSON 视为半可信配置，仍需验证密钥/目标/范围；
- FFmpeg/ffprobe 是用户显式选择的外部程序，其自身漏洞不在本工具控制范围内。

## 2. 不执行不可信代码

| 风险 | 防护 |
| --- | --- |
| 反编译源码被 `exec`/`eval` | 代码中不存在 `exec()`/`eval()`/动态导入；只调用 `ast.parse` 与 AST 遍历 |
| 导入游戏模块 | 不向 `sys.path` 添加游戏目录，不导入恢复的模块 |
| 格式化字符串/模板执行 | 不从源码执行表达式；常量折叠只支持字面量、`int`、`ord`、`chr`、`bytes` 等纯操作 |
| 反编译器副作用 | uncompyle6 只接收文件路径并写入内存 `StringIO`；捕获 `SystemExit`/异常 |
| 反汇编副作用 | xdis 只读取/反序列化 code object 并生成文本，不导入、不执行；反汇编文本只做正则/字面量分析 |

AST 常量折叠是受限解释，不是 Python 求值：只接受白名单节点和操作，限制递归深度、
整数位宽和移位量。反汇编回退的 XOR 提取只使用最近的 `LOAD_CONST` 和变量名，
置信度被标记为低值，不视为确定结论。

## 3. 安全 pickle 读取

RPA 索引通过 `pickletools.genops` 逐 opcode 解释，**从不调用** `pickle.load` 或
`pickle.loads`。

允许的值类型：

- `None`、`bool`、`int`、`float`、`str`、`bytes`
- `tuple`、`list`、`dict`
- 字典键只能是上述基础值或由基础值组成的 tuple

明确拒绝：

- `GLOBAL`（除下方 bytes 构造白名单）、`STACK_GLOBAL`
- `REDUCE`（除下方 bytes 构造白名单）、`BUILD`
- `INST`、`OBJ`、`NEWOBJ`、`NEWOBJ_EX`
- `PERSID`、`BINPERSID`、`EXT1/2/4`
- `NEXT_BUFFER`、集合操作
- 未知 opcode、循环引用、过深嵌套

### bytes 构造白名单

Python 3 在协议 0–2 中把 `bytes` 表示为：

- `_codecs.encode(str, "latin1")`
- 空 bytes 的 `__builtin__ bytes()`

现代 Ren'Py 的 RPA 索引可能包含 bytes 前缀，因此解释器对这两个模式做**结构化**处理：
只接受固定全局名、两个字符串参数和 latin1/utf-8/ascii 编码，或空参数/0–255 整数列表。
不会导入模块，也不会调用任意 callable。其他任何 `GLOBAL`/`REDUCE` 均拒绝。

### 资源上限

默认值（可通过 `PickleLimits`/`RpaLimits` 调整）：

- 输入 64 MiB
- 单字符串 16 MiB
- 解码总字节 128 MiB
- 容器元素总数 1,000,000
- 栈/memo 200,000
- 结构深度 80
- 节点数 1,000,000

### 已知限制

- 为保持安全性，合法的复杂 pickle 对象（如 numpy 数组、自定义类）会被拒绝；
  这不是通用 unpickler。
- 允许 bytes 构造白名单会扩大极小的攻击面，但不会执行任意函数。

## 4. RPA 解析与解压

- 头部最多读取 4 KiB；索引压缩数据最多 64 MiB；解压后最多 256 MiB。
- 反汇编输入字节码最多 128 MiB，生成的文本最多 32 MiB。
- 使用 `zlib.decompressobj` 的 `max_length` 分块解压，超限立即报错。
- 索引偏移、文件大小、offset/length/prefix 全部做范围校验；拒绝与索引区域重叠的数据段。
- 不信任头部 key：候选 key 必须让**所有**分段落在合法范围，否则拒绝导出。
- 索引自身被 XOR 的变体支持显式 `index` 规则和 header key 回退，但候选数量受限。

## 5. 路径与写入安全

资源名经过 `normalize_archive_name`：

- 拒绝绝对路径、`..`、空段、NUL/控制字符；
- 拒绝 Windows 盘符、ADS 冒号、保留设备名（CON/NUL/COM1 等）；
- 反斜杠统一为 `/`；
- 校验大小写冲突并给出警告。

导出器：

- 输出根不能位于游戏/归档根内；
- 重新校验名称，防止手工构造的 `RpaEntry` 绕过解析器；
- 拒绝输出路径中的符号链接目录；
- 先写同目录 `.part` 临时文件，`os.replace` 原子落盘；
- 默认不覆盖已有文件；空文件过滤；
- 单文件失败可继续，并写入结构化报告。

## 6. 网络与外部进程

- 项目代码不包含 HTTP 客户端、上传逻辑或远程下载逻辑。
- 媒体转换只接受本地存在的文件；FFmpeg/ffprobe 命令带 `-protocol_whitelist file`，
  拒绝网络协议。
- 命令以 `list[str]` 传给 `subprocess.run`，`shell=False`，不使用字符串拼接 shell。
- 输出使用临时文件，失败清理；输入文件不写入。
- 反汇编使用 xdis 读取 code object；不会把反汇编文本传给 Python 解释器。
- 程序不会在 `scan`/`analyze`/`export` 中启动 FFmpeg；只有显式 `convert` 子命令会调用。

**注意**：FFmpeg/ffprobe 是外部程序，其解析器和编解码器可能有独立漏洞。只处理可信来源的
媒体，并保持 FFmpeg 更新。

## 7. GUI 与打包

- Tkinter GUI 只是 CLI 模块的本地前端；所有分析/导出/转换仍在后台线程调用同一套
  受限函数，不在 GUI 进程内执行游戏代码。
- GUI 的工作目录、规则文件和导出目录会接受与 CLI 相同的“不得位于游戏根目录内”检查。
- 语言设置仅保存 `zh_CN` 或 `en` 到本地 `%APPDATA%\rpa-loader-analyzer\settings.json`，
  不包含游戏路径或分析数据。
- 后台线程只通过队列向主线程发送日志/结果；Tk 控件只在主线程更新。
- PyInstaller 单文件 EXE 会解压运行时依赖到系统临时目录，这是打包工具的标准行为；
  如组织策略禁止该行为，请使用 `--onedir` 或从源码运行。

## 8. 已知功能限制

- 不支持所有 RPA 变体；未知头部/索引会结构化失败，而不是猜测。
- 高强度控制流混淆、反调试、动态密钥可能使静态分析失败。
- `uncompyle6` 支持的 Python 版本有限；失败时会回退到 xdis 反汇编，但反汇编规则是
  启发式的，可能需要人工核对。
- 多密钥、分段数据、头部 key 为诱饵等情况依赖评分与规则质量，可能无法唯一确定。
- `uncompyle6`、`xdis` 和 FFmpeg 都是第三方解析器；本工具不执行游戏代码，但第三方
  解析器自身的漏洞仍需通过保持依赖更新、隔离环境处理未知样本来控制。
- FFmpeg 硬件编码是否可用取决于驱动、设备和 FFmpeg 构建。

## 9. 安全使用建议

1. 在隔离的虚拟机或专用目录中处理未知样本；
2. 只对拥有合法授权的文件运行；
3. 输出到独立目录，不要把报告/资源写回游戏目录；
4. 处理前备份原始文件；工具本身不会修改它们；
5. 不将游戏二进制、源码或提取资源上传到网络；
6. 发现安全问题时，先在本地复现并保留最小样本，不要公开未脱敏的游戏内容。
